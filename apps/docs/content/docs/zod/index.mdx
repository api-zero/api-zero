`api.get<User>("/users/1")` is a promise you make to yourself. Nothing checks it.

If the API renames a field, drops one, or returns `null` where you expected a
string, TypeScript stays quiet and your code fails somewhere else entirely —
usually in a component, with a message that says nothing about the API.

`@api-zero/zod` closes that gap. The schema validates the payload **and**
produces the type, so the two cannot disagree.

## Installation

Both `@api-zero/core` and `zod` are peer dependencies: you keep control of the
versions, and there is only ever one copy of each in your tree.

<Tabs items={['npm', 'pnpm', 'yarn', 'bun']} defaultIndex={1}>

## How it fits the lifecycle

A schema is a transform, not a separate mechanism.

<Accordions>
  <Accordion title="A response schema runs after parsing, before interceptors">
    So a response interceptor sees already-validated, already-transformed data —
    not a raw payload it would have to re-check.
  </Accordion>
  <Accordion title="A body schema runs before the request is built">
    So an invalid payload never reaches the transport, and the failure arrives
    with `target: "body"` rather than as a `400` from the server.
  </Accordion>
  <Accordion title="Validation failures are never retried">
    A payload that failed the schema fails identically on the next attempt.
    `isRetryable()` returns `false`, so the retry policy skips it.
  </Accordion>
</Accordions>
