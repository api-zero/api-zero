`fetch` cannot report upload progress. That is not an api-zero limitation — the
Fetch standard has no mechanism for it. So when a request asks for progress,
api-zero sends it through `XhrTransport` instead.

<Callout type="warn">
  XHR exists only in browsers. Asking for progress in Node or on an Edge runtime
  cannot work, so keep progress callbacks in client-side code.
</Callout>

## Upload

<include meta='title="upload.ts"'>../../../../../../examples/src/upload-progress.ts</include>

Check `lengthComputable` first. Without a `Content-Length` the total is unknown,
and dividing by it produces `Infinity` or `NaN` — which is how progress bars end
up stuck or full from the start.

`FormData` is detected automatically and the `Content-Type` header is removed so
the browser can generate the multipart boundary. Do not set it yourself.

## Download

<include meta='title="download.ts"'>../../../../../../examples/src/download-progress.ts</include>

`responseType: "blob"` matters for binary payloads: the default `"json"` would
try to parse a PDF as JSON and fail.

Download progress also needs a `Content-Length` from the server. Chunked or
compressed responses often lack one, in which case `total` is `0` — show an
indeterminate spinner rather than a percentage.
