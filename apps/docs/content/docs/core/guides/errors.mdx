Native `fetch` gets this backwards. A DNS failure rejects with
`TypeError: Failed to fetch`, while a `500` **resolves successfully** — so a
correct handler needs two unrelated code paths and most codebases only write
one.

api-zero normalizes everything into a single `ApiError`: HTTP statuses, network
failures, timeouts, cancellations and validation failures alike.

## Branching cleanly

The helpers exist so call sites read as intent rather than arithmetic on status
codes.

<Accordions>
  <Accordion title="A missing resource is often not an error">
    `isNotFound()` usually means an empty state, not a failure screen. Returning
    `null` and letting the UI decide keeps a normal outcome out of your error
    reporting.
  </Accordion>
  <Accordion title="An expired session is a redirect, not a message">
    `isUnauthorized()` calls for re-authentication. Showing the raw message to
    the user tells them nothing they can act on — see
    [authentication](/docs/core/guides/authentication) for refreshing the token
    instead.
  </Accordion>
  <Accordion title="A 4xx you caused will not fix itself">
    `is4xx()` other than 401, 408 and 429 means the request was wrong. Retrying
    produces the same answer; log it and fix the caller.
  </Accordion>
  <Accordion title="A 5xx is worth trying again">
    `is5xx()` and network failures are transient by nature, which is exactly what
    the [retry policy](/docs/core/guides/retries) automates.
  </Accordion>
</Accordions>

## Reporting

### Logging

`toJSON()` returns a flat object with the message, status, flags, attempt and
the resolved URL and method — without the native `Response`, which does not
serialize.

```typescript
logger.error("request failed", error.toJSON());
```

Logging `error.message` alone throws away the context that makes an incident
diagnosable: which URL, which attempt, which underlying cause.

### Centralising it

A response interceptor sees every failure before the caller does, which is where
cross-cutting concerns belong — telemetry, a toast, a redirect.
