---
title: Configuration
description: Every option on the client and on a single request.
---

Configuration lives in two places. `ApiClientConfig` is passed to
`createClient` and applies to every request. `RequestOptions` is passed to a
single call and overrides the client for that call only.

Per-request wins, option by option. Setting `timeout` on one request does not
disturb the headers or the retry policy configured on the client.

## `ApiClientConfig`

| Option | Type | Default | Description |
| ------ | ---- | ------- | ----------- |
| `baseURL` | `string` | `""` | Prefix for every endpoint. |
| `timeout` | `number` | `30000` | Milliseconds. `0` disables the timeout. |
| `headers` | `Record<string, string>` | `{}` | Sent with every request. |
| `credentials` | `RequestCredentials` | unset | Standard Fetch credentials mode. |
| `retry` | `RetryConfig \| false` | `false` | Off unless configured. See [Retries](/docs/core/api-reference/retry). |
| `transformRequest` | fn or fn[] | — | Runs before request interceptors. |
| `transformResponse` | fn or fn[] | — | Runs after the response is parsed. |
| `paramsSerializer` | `ParamsSerializerConfig` | — | How arrays become query strings. |
| `transport` | `Transport` | auto | Replaces the network layer entirely. |

<Callout type="info">
  **Retries are off by default.** A client that silently repeats requests is a
  client that can double-charge a customer. Turning them on is a decision you
  make per API, with a policy you chose.
</Callout>

## `RequestOptions`

Everything above except `transport`, plus:

| Option | Type | Default | Description |
| ------ | ---- | ------- | ----------- |
| `params` | `object` | — | Query parameters. |
| `signal` | `AbortSignal` | — | Caller cancellation. Composes with `timeout`. |
| `responseType` | `"json" \| "text" \| "blob" \| "arrayBuffer"` | `"json"` | How to read the body. |
| `onUploadProgress` | `(event) => void` | — | Browser only. Switches to `XhrTransport`. |
| `onDownloadProgress` | `(event) => void` | — | Browser only. Switches to `XhrTransport`. |
| `validateResponse` | `(data) => boolean \| Promise<boolean>` | — | Reject a structurally valid but unacceptable body. |
| `onValidationError` | `(error: ApiError) => void` | — | Called when validation rejects. |
| `metadata` | `Record<string, unknown>` | `{}` | Carried through the context, untouched. |

### `timeout`

`0` disables it. This works because the value is resolved with `??` rather than
`||`, so a deliberate zero is not mistaken for "unset" — a distinction many
clients get wrong.

### `metadata`

An untouched bucket that travels with the request context. Interceptors and
transports can read it, which is how you tag a request as "skip auth refresh"
or attach a correlation id without inventing a header.

## Query parameters

<include>../../../../../../examples/src/query-params.ts</include>

Arrays need a convention, and no standard picked one. `paramsSerializer`
chooses:

| `arrayFormat` | `{ tag: ["a", "b"] }` becomes |
| ------------- | ----------------------------- |
| `"brackets"` | `tag[]=a&tag[]=b` |
| `"repeat"` | `tag=a&tag=b` |
| `"comma"` | `tag=a,b` |

Match whatever your backend parses. Guessing produces a request that looks
correct and silently returns the wrong rows.

## Transforms

`transformRequest` runs on the body before request interceptors.
`transformResponse` runs on the parsed body before validation. Both accept a
function or an array applied in order, and both may be async.

Client-level transforms run first, then per-request ones. This is how
[`@api-zero/zod`](/docs/zod) plugs in: a schema is just a response transform
that throws on a mismatch.
