A transport is everything between a resolved request and a parsed response.
Because it is a single method, replacing it replaces the entire network layer —
which is what makes tests deterministic without patching globals.

```typescript
interface Transport {
  send(context: RequestContext): Promise<TransportResponse>;
}
```

## The built-in transports

<Cards>
  <Card icon={<Globe className="text-sky-500" />} title="FetchTransport" description="Used everywhere. Browsers, Node 22+, Edge runtimes." />
  <Card icon={<Gauge className="text-fuchsia-500" />} title="XhrTransport" description="Browsers only. Selected automatically when upload or download progress is requested." />
</Cards>

Selection happens per request: a custom `transport` wins outright, otherwise
asking for progress selects XHR, otherwise Fetch. `fetch` has no mechanism for
upload progress, which is the whole reason the XHR path exists.

<Callout type="warn">
  XHR exists only in browsers. Requesting progress in Node or on an Edge runtime
  cannot work — there is nothing to switch to.
</Callout>
