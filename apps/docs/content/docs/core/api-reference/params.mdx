Pass `params` and api-zero builds the query string for you.

## Arrays

Arrays are the only genuinely ambiguous case: HTTP never standardised how to
encode one, so every backend framework picked differently. `paramsSerializer`
lets you match yours.

| `arrayFormat` | `{ tag: ["a", "b"] }` becomes |
| ------------- | ----------------------------- |
| `"brackets"` (default) | `tag[]=a&tag[]=b` |
| `"repeat"` | `tag=a&tag=b` |
| `"comma"` | `tag=a,b` |

```typescript
await api.get("/posts", {
  params: { tag: ["typescript", "http"] },
  paramsSerializer: { arrayFormat: "repeat" },
});
```

Getting this wrong is quiet. The request succeeds, the server parses what it can,
and you get the wrong rows back with a `200`. Check what your backend expects
rather than assuming.

## What gets skipped

`null` and `undefined` values are dropped entirely — no empty `key=` in the
output. That means an optional filter can be passed straight through without
guarding it:

```typescript
await api.get("/users", {
  params: { role: "admin", team: selectedTeam ?? undefined },
});
```

## What gets stringified

Every other value goes through `String(value)`. Numbers and booleans behave as
you would expect. Two cases do not:

| Value | Produces |
| ----- | -------- |
| `new Date()` | The full `toString()` form, not ISO 8601 |
| `{ a: 1 }` | `[object Object]` |

<Callout type="warn">
  Neither is rejected, so a nested object silently becomes the literal string
  `[object Object]` in your URL. Format dates and flatten objects before passing
  them:

```typescript
params: { since: date.toISOString(), sort: "name:asc" }
```
</Callout>

## Encoding

Serialization uses the platform's `URLSearchParams`, so keys and values are
percent-encoded correctly, including spaces and non-ASCII characters. You do not
need to encode anything yourself — doing it produces double-encoded values.

## Where to set it

`paramsSerializer` works on the client, applying to every request, or on a single
request. Per-request wins.
