`ApiClient` holds your base URL, headers, auth, interceptors and retry policy,
and applies them to every request made through it.

Create one and export it. A client per call throws away everything you
configured.

## Creating a client

<include meta='title="lib/api.ts"'>../../../../../../examples/src/create-client.ts</include>

`createClient(config?)` is the recommended factory. `new ApiClient(config?)` is
equivalent — the factory exists so call sites read as intent rather than
construction.

## HTTP verbs

```typescript
get   <TResponse = unknown, TParams = Record<string, unknown>>(endpoint, options?)
delete<TResponse = unknown, TParams = Record<string, unknown>>(endpoint, options?)

post  <TResponse = unknown, TBody = unknown, TParams = Record<string, unknown>>(endpoint, body?, options?)
put   <TResponse = unknown, TBody = unknown, TParams = Record<string, unknown>>(endpoint, body?, options?)
patch <TResponse = unknown, TBody = unknown, TParams = Record<string, unknown>>(endpoint, body?, options?)
```

Every one returns `Promise<TResponse>` — the parsed body, not a `Response`
wrapper. There is no `.data` to unwrap.

<include meta='title="users.ts"'>../../../../../../examples/src/http-verbs.ts</include>

<Callout type="warn">
  `TResponse` defaults to `unknown`, not `any`. That is deliberate: `any`
  silently disables type checking downstream, while `unknown` forces you to
  either declare the shape or narrow it. Declaring it is a promise you are
  making to yourself — for payloads you do not control, have it
  [checked at runtime](/docs/zod).
</Callout>

## Uploads and progress

<include meta='title="upload.ts"'>../../../../../../examples/src/upload-progress.ts</include>

`FormData` is detected and any `Content-Type` header is **removed** — the header
is matched case-insensitively. This is intentional: a multipart body needs a
boundary parameter that only the platform can generate, so setting the header
yourself produces a request the server cannot parse.

`URLSearchParams`, `Blob` and `ArrayBuffer` pass through untouched. Anything else
is JSON-encoded and gets `Content-Type: application/json`, unless you already set
one.

Requesting progress switches the request to `XhrTransport`, because `fetch`
cannot report upload progress. Download progress works the same way:

<include meta='title="download.ts"'>../../../../../../examples/src/download-progress.ts</include>

<Callout type="warn">
  XHR exists only in browsers. Asking for progress in Node or on an Edge runtime
  cannot work — keep progress callbacks on the client side.
</Callout>

`setAuthToken(token)` is shorthand for `Authorization: Bearer <token>`.
`setBasicAuth(user, pass)` base64-encodes the pair. `clearAuth()` removes the
header.

## Interceptors

```typescript
client.interceptors.request  // InterceptorManager<RequestContext, unknown>
client.interceptors.response // InterceptorManager<ResponseContext, ApiError>
```

Request handlers receive a `RequestContext` — method, resolved URL, body, params,
headers, attempt and metadata. Response handlers receive a `ResponseContext` with
parsed `data`, status, headers and timing; rejection handlers receive an
`ApiError`.
